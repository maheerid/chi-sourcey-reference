## Included

Both public packages selected by `go list ./...` are generated: the root chi router package and its middleware package. The snapshot contains **128 exported declaration records**, including functions, types, variables/constants, and methods. The generated reference preserves signatures, comments, and source locations across the library's source files. The symbol inventory in the evidence identifies each package and declaration individually.

The six guide pages add tested usage and composition explanations. Search, API navigation, page tables of contents, copyable signatures, source links, a sitemap, and `llms.txt` are generated by Sourcey.

The native adapter displays method signatures without receivers under their owning type. In Sourcey 3.6.12, `HeaderRouter.Route` retains an erroneous receiver fragment. The reproducible snapshot repair removes that fragment after checking the exact pinned source declaration. Its [before/after record](/chi-sourcey-reference/evidence/snapshot-corrections.json) documents the correction.

## Boundaries

Private implementation details are excluded. Underscore-prefixed `_examples` directories are not packages in the selected `./...` scope. Upstream's current snapshot has no extracted Go `Example` blocks; the executable examples in this documentation project are independent companion tests rather than invented upstream examples. HTTP behavior beyond the three documented test groups has not been exhaustively verified by those examples; upstream's package tests are run separately.

## Verify a page

1. Open its **Defined in** link to the vendored file.
2. Compare the file against the same path at the pinned upstream commit.
3. Check the SHA-256 in [source-manifest.json](/chi-sourcey-reference/evidence/source-manifest.json).
4. Rebuild from the committed [godoc.json](https://github.com/maheerid/chi-sourcey-reference/blob/main/godoc.json).
5. Inspect the [structured evidence](/chi-sourcey-reference/evidence/evidence.json) and [delivery report](/chi-sourcey-reference/evidence/report.md).

The governed build uses the real runx CLI. Its sealed receipt records the process result and named output artifact. The receipt is signed in **local development mode**: digest, content-address, and signature checks pass with the explicit development flag. An independently trusted production key and receipt-tree lineage are not established. See the [development verdict](/chi-sourcey-reference/evidence/receipt-verification-development.json) and [production verification result](/chi-sourcey-reference/evidence/receipt-verification.json). These records describe the local execution; they do not independently guarantee every statement in the guides.
